# UMODZI CONNECT – PROFESSIONAL ANIMATED, THEME-AWARE SPLASH SCREEN

## ROLE

Act as a Senior Frontend Engineer, UI/UX Designer, PWA Specialist, and QA Automation Engineer.

Your task is to implement a professional, modern, animated splash screen for the existing Umodzi Connect application.

The implementation must integrate seamlessly with the existing Next.js architecture, branding, theme provider, authentication system, routing, and PWA configuration.

This is an enhancement to the existing application, NOT a redesign or replacement of existing functionality.

**IMPORTANT: All implementation changes MUST be tested and verified before they are considered ready for deployment.**

---

# 1. OFFICIAL UMODZI CONNECT LOGO – STRICT REQUIREMENT

The splash screen MUST use the exact official Umodzi Connect logo already present in the existing codebase.

Before making changes:

1. Inspect the project's assets and identify the existing official logo.
2. Locate all existing references to the logo.
3. Identify the correct image format and available light/dark variants.
4. Reuse the existing logo asset in the splash screen.

STRICTLY PROHIBITED:

- Generating a new logo.
- Creating an alternative logo.
- Replacing the logo with plain text.
- Using an AI-generated logo.
- Redrawing or modifying the logo.
- Changing its original proportions.
- Cropping or distorting the logo.
- Introducing unrelated branding.

The logo must remain visually identical to the existing application logo.

Only animate its presentation, not its artwork.

---

# 2. PROFESSIONAL VISUAL DESIGN

Create a premium, minimalist application launch experience.

Use the existing Umodzi Connect design system.

The splash screen should contain:

- Official Umodzi Connect logo.
- Application name where appropriate.
- Existing brand typography.
- Tagline: "Connecting Skills. Solving Problems."
- Elegant loading indicator.
- Contextual loading message.
- Subtle branded decorative elements where appropriate.

The design must look professional on both smartphones and tablets.

Avoid excessive gradients, unnecessary illustrations, flashy effects, excessive text, and generic splash-screen templates.

Use consistent spacing, visual hierarchy, typography, and alignment.

---

# 3. ADAPTIVE SYSTEM COLOUR THEME

The splash screen MUST follow the existing application theme system.

Do not introduce a separate theme provider or independent colour configuration.

### Light mode

- Use existing light-theme background tokens.
- Use existing primary text colours.
- Use existing accent colours.
- Maintain a clean, bright, premium appearance.

### Dark mode

- Use existing dark-theme background tokens.
- Use existing text and surface colours.
- Use existing accent colours.
- Maintain appropriate contrast and readability.

### System theme

When the application is configured to follow the device theme:

- Respect the operating system's light/dark preference.
- Apply the correct theme before rendering the splash screen.
- Prevent a flash of the incorrect theme during launch.

### Saved theme preference

If the user has explicitly selected a theme within the application, respect that preference instead of overriding it with the operating system setting.

The splash screen must respond correctly to supported theme changes.

---

# 4. PROFESSIONAL ANIMATED FEATURES

Implement subtle, smooth animations that make Umodzi Connect feel like a professionally developed mobile application.

### Animation sequence

1. Background smoothly fades into view.
2. Official logo fades in and gently scales from approximately 90% to 100%.
3. Application branding reveals with a subtle upward movement.
4. Tagline fades into view.
5. Teal and coral accents animate subtly using existing theme colours.
6. Loading indicator rotates smoothly.
7. Loading text displays the current initialization activity where appropriate.
8. When initialization finishes, the splash screen transitions smoothly into the application.

### Additional animation effects

Where appropriate, implement:

- Subtle logo breathing animation.
- Gentle background movement.
- Smooth opacity transitions.
- Lightweight animated gradient accents.
- Smooth loading indicator rotation.
- Elegant exit fade and transition.

Animations must be coordinated using staggered timing.

Do not use excessive bouncing, flashing, rapid scaling, or distracting effects.

The splash screen should feel refined, not like an animated advertisement.

# 6. PWA NATIVE SPLASH SCREEN INTEGRATION

Inspect the existing PWA configuration before changing anything.

Verify:

- Web App Manifest.
- Application name.
- Short name.
- Theme colour.
- Background colour.
- Display mode.
- Application icons.
- Icon sizes.
- Service worker configuration.

Where supported, configure native PWA launch presentation to remain consistent with the application's branding.

IMPORTANT:

Native operating-system splash screens and application-rendered splash screens are different mechanisms.

Use supported platform configuration and do not assume CSS animations can control the native operating-system launch screen.

Avoid duplicate or unnecessarily prolonged splash experiences.

---

# 7. APPLICATION INITIALIZATION AND AUTHENTICATION

Integrate the splash screen with the existing application initialization process.

The expected sequence:

1. Application starts.
2. Correct theme is established.
3. Splash screen becomes visible.
4. Existing authentication session is restored.
5. Required application configuration is initialized.
6. User role is identified.
7. Initial route is resolved.
8. Appropriate application screen loads.
9. Splash screen transitions out.

### Routing requirements

- Authenticated customers must reach their customer dashboard.
- Authenticated technicians must reach their technician dashboard.
- Unauthenticated users must reach the appropriate welcome or login screen.
- Existing role-based route protection must remain intact.

### Loading requirements

- Do not introduce artificial loading delays.
- Do not block normal navigation.
- Do not display the splash screen repeatedly during ordinary internal navigation.
- Do not create an infinite loading state.
- Handle authentication failures appropriately.
- Provide retry or recovery functionality when initialization fails.

The splash screen should only cover the actual application initialization period.

---

# 8. PERFORMANCE AND ACCESSIBILITY

The implementation must remain lightweight.

Requirements:

- Prefer CSS animations and transitions.
- Avoid unnecessary animation libraries.
- Avoid large assets.
- Avoid expensive continuous animations.
- Respect `prefers-reduced-motion`.
- Avoid blocking the main application thread.
- Prevent layout shifts.
- Maintain readable contrast.
- Support different screen densities.
- Avoid unnecessary component re-renders.

Users with reduced-motion preferences should receive a simplified presentation with minimal or no decorative animation.
